Marketplace Core / Integration / Odoo）可启动、测试数据可重复初始化、健康检查与冒烟测试
可自动执行、启动/停止/备份脚本可用。阶段 0 **不实现**完整业务功能。

## Agent 修改边界

详见根 `README.md`「目录所有权」一节。要点：一个应用目录的**代码**归 dev、**配置**归
config、**运行/发布**归 ops；跨边界修改必须在 issue 中声明。契约（`packages/contracts/`）
归 architect，仅读使用；测试（`tests/`）归 qa。

## 已知问题

1. **Woo 环境 docker 镜像缺 mysql-client + MySQL8 自签证书 TLS 校验 + CRLF 破坏 shell 脚本**
   — 由追加 issue CESH-31 修复（`default-mysql-client`、`wp db check
   --ssl-verify-server-cert=0`、`.gitattributes` 强制 LF），修复分支 `agent/config/eca302ee01f4`
   的 PR #10 待合并进 `main`。合并后 Woo 冒烟即可全绿。
2. **沙箱网络不稳定**：`github.com` 与 `auth.docker.io` 在运行时沙箱中时断时续，导致
   `git push` 与镜像构建间歇失败。基础镜像（wordpress/odoo/postgres/mysql/python:3.12-slim）
   已本地缓存，短期可绕过；长期建议配置 Docker registry mirror 或代理。
3. **`gh` CLI 未安装**：agent 无法用 `gh` 开 PR，PR 需人工通过 Web UI 或 REST API 创建
   （已写入 dev/config/ops 的提示词交接规则）。
4. **Python 路径污染**：曾出现陈旧 editable 安装（`shopstore-core`）指向旧 workdir 导致
   `from app.config import reset_settings` 被劫持。已修复（`apps/core/tests/conftest.py`
   显式 sys.path 引导 + 卸载陈旧安装）；教训是每个 agent 用独立 venv、不共享 site-packages。
5. **模型空转**：ops/qa 原配 `glm-5.3` 系列曾出现「读多写少、中途空转」现象，已切换为
   `deepseek-v4-pro`。

## 本地环境差异

- 运行时为 Windows（PowerShell 5.1），`core.autocrlf=true`；脚本需经 `.gitattributes`
  强制 LF 才能进容器执行。
- Docker Desktop（Engine 29.x）+ Compose V2；基础镜像已本地缓存。
- 沙箱无法稳定访问外网 registry / github，需要人工网络或镜像加速。
