# 阶段性开发方案

## 1. 开发方法

项目采用分阶段开发和 issue 派发模式。

原则：

- 先闭环，后丰富
- 先复用 WooCommerce 和 Odoo，缺失能力再开发
- 每个阶段都必须可验收
- 每个 issue 都要有明确 owner、输入、输出和验收标准
- 不允许多个 agent 无边界地修改同一模块

## 2. 阶段总览

```text
阶段 0：项目基座
阶段 1：最小业务闭环
阶段 2：履约增强
阶段 3：经营闭环
阶段 4：Faire-like 体验增强
```

## 3. 阶段 0：项目基座

目标：让所有 agent 可以在统一环境中开发。

### 交付内容

- 项目目录结构
- Docker / 本地启动方案
- WordPress + WooCommerce 基础安装
- Odoo 基础安装
- Core 服务骨架
- 数据库配置
- 环境变量模板
- 测试数据结构
- issue 模板

### 推荐 issue

```text
ISSUE-0001 项目目录和启动规范
Owner: rebuild-config

ISSUE-0002 WooCommerce 基础安装和配置
Owner: rebuild-config

ISSUE-0003 Odoo 基础安装和模块配置
Owner: rebuild-config

ISSUE-0004 Core 服务骨架
Owner: rebuild-dev

ISSUE-0005 第一版 API / 数据模型契约
Owner: rebuild-architect

ISSUE-0006 Product / Order 投影和 ID 映射契约
Owner: rebuild-architect
```

### 验收标准

- Woo 可以访问
- Odoo 可以访问
- Core 可以启动
- Core 可以连接数据库
- 有统一启动文档
- 有测试账号和测试 SKU

## 4. 阶段 1：最小业务闭环

目标：跑通 B2B 下单到 Odoo 发货的完整链路。

### 交付内容

- 买家注册 / 登录
- 买家认证状态
- 品牌和商品展示
- 批发价展示
- MOQ 展示和校验
- 无支付下单
- Core Marketplace 订单
- Core -> Odoo 创建销售单
- Odoo 确认销售单
- Odoo 创建交货单
- 仓库手动发货
- Odoo -> Core 状态回传
- Core -> Woo 前台状态展示
- 同步失败记录和人工重试

### 推荐 issue

```text
ISSUE-0101 Retailer / Brand / Product / Order 数据模型
Owner: rebuild-architect

ISSUE-0102 Product 创建链路和三系统投影契约
Owner: rebuild-architect

ISSUE-0103 Core 基础 API
Owner: rebuild-dev

ISSUE-0104 Woo 轻量桥接插件
Owner: rebuild-dev

ISSUE-0105 Woo 前台 B2B 页面和无支付 checkout
Owner: rebuild-dev

ISSUE-0106 Odoo Sales + Inventory + Delivery 基础配置
Owner: rebuild-config

ISSUE-0107 Integration：Core 订单命令 -> Odoo 销售单创建
Owner: rebuild-dev

ISSUE-0108 Integration：Odoo -> Core 履约状态回传
Owner: rebuild-dev

ISSUE-0109 同步失败、幂等和人工重试
Owner: rebuild-dev

ISSUE-0110 阶段一端到端验收
Owner: rebuild-qa

ISSUE-0111 阶段一发布和回滚说明
Owner: rebuild-ops
```

### 验收标准

```text
买家注册
  -> 运营审核通过
  -> 买家看到批发价
  -> 买家按 MOQ 下单
  -> Core 创建订单
  -> Odoo 创建销售单
  -> Odoo 创建交货单
  -> 仓库发货
  -> 前台订单状态更新
```

## 8. Issue 模板

每个开发 issue 建议使用以下格式：

```text
# ISSUE-XXXX 标题

## 背景

## 目标

## Owner

## 依赖

## 修改范围

## 输入

## 输出

## 验收标准

## 风险
```

## 9. Agent 工作边界

| Agent | 主要修改范围 |
| --- | --- |
| rebuild-pm | docs、issue、排期、验收记录 |
| rebuild-architect | docs、contracts、状态机、数据模型 |
| rebuild-config | infra、apps/woo 配置、apps/odoo 配置 |
| rebuild-dev | apps/core、apps/woo/plugins、apps/odoo/addons、apps/integration |
| rebuild-qa | tests、验收用例、测试报告 |
| rebuild-ops | infra、scripts、部署和备份文档 |

## 10. 开发节奏建议

每个阶段采用以下节奏：

```text
PM 拆 issue
  -> Architect 冻结契约
  -> Config 搭基座和数据
  -> Dev 开发缺失能力
  -> QA 端到端验收
  -> Ops 打包和发布说明
```

阶段一不要等所有模块都完美后再集成，应尽早跑通一条端到端测试订单。
