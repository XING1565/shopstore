# 本地开发说明

本文件说明如何基于本仓库搭建本地开发环境。阶段 0 仍在建设中，
一键脚本与 Docker 编排由 `ops` 在 ISSUE-0010 提供；此处给出目录与手工步骤。

## 目录结构

```
shopstore/
  apps/core          Marketplace Core（业务模型/规则）
  apps/woo           WordPress + WooCommerce（前台）
  apps/odoo          Odoo ERP（Sales/Inventory/Delivery）
  apps/integration   Integration Layer（Adapter / 同步任务）
  packages/contracts 契约（openapi/events/schemas）
  packages/test-data  固定测试数据
  infra/docker, scripts, env  编排 / 脚本 / 环境变量模板
  tests/             smoke / integration / e2e
```

目录所有权见根 `README.md` 与各应用 `README.md`。

## 前置要求

- 各应用版本固定清单见 `docs/版本清单.md`（ISSUE-0002 产出，尚未发布）。
- 环境变量模板见 `infra/env/*.env.example`。

## 从模板生成本地环境

每个需要运行的应用复制对应模板并填写本机值（真实 `.env` 不提交）：

```powershell
Copy-Item infra/env/core.env.example apps/core/.env
Copy-Item infra/env/woo.env.example   apps/woo/.env
Copy-Item infra/env/odoo.env.example  apps/odoo/.env
Copy-Item infra/env/integration.env.example apps/integration/.env
```

> 具体读取 `.env` 的启动方式（Docker Compose / 本地进程）由 ISSUE-0010 的
> `infra/scripts` 与 `infra/docker` 固化，届时按 `docs/版本清单.md` 锁定版本运行。

## 约定

- 本地运行一律使用示例/测试凭据，绝不把真实生产配置写进仓库。
- 改动范围遵守各应用 README 中的 Owner 边界。
- 开发完成后按 `docs/分支与提交规范.md` 提交。
