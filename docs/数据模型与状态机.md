## 1. 范围与定位

本任务落地 Core 的四类核心模型与订单状态机，作为阶段 1 的业务地基：

- **Retailer（买家）**：认证状态机（Pending → Approved）+ 运营审核字段。
- **Brand（品牌）**：品牌档案（阶段一由运营代维护）。
- **Product（商品）**：批发价、MOQ、SKU 与三系统外部 ID 映射。
- **Order（订单）**：Marketplace 订单状态机 + 外部 ID 映射。

遵循两条架构底线（`docs/架构方案.md` 第 12 节）：

1. 所有外部系统 ID 必须在 Core 记录映射；
2. Core 是订单主权系统，Odoo 是库存 / 履约主权系统，Core 不复制 Odoo 全量数据。

## 2. 命名与类型约定

| 项 | 约定 | 来源 |
| --- | --- | --- |
| 主键 | Core 自生成 ID，UUID v4，以字符串存储 | `conventions.md` §1 |
| 时间字段 | `created_at` / `updated_at`，UTC | `conventions.md` §6 |
| 金额 | 最小单位整数 + ISO 4217（禁止浮点数） | `conventions.md` §7、`money.schema.json` |
| 枚举 | snake_case，非原生枚举（VARCHAR + CHECK） | `conventions.md` §8 |
| 表名 | 小写下划线，无前缀（Core 无平台前缀约定） | `命名规范.md` §数据库 |

枚举列采用 `native_enum=False`（VARCHAR + CHECK），而非 PostgreSQL 原生 enum：新增状态值只需更新 CHECK 约束，无需 `ALTER TYPE`，契合"可稳定升级"目标。

## 3. 模型定义

模型代码位于 `apps/core/app/models/`，迁移位于 `apps/core/migrations/versions/0002_*.py`。

### 3.1 Retailer（`retailers`）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | String(36) | PK | UUID v4 |
| `email` | String(320) | NOT NULL, UNIQUE | 登录 / 唯一标识 |
| `company_name` | String(255) | NOT NULL | 公司名 |
| `contact_name` | String(255) | NULL | 联系人 |
| `phone` | String(64) | NULL | 电话 |
| `status` | Enum | NOT NULL, default `pending` | 认证状态 |
| `reviewed_by` | String(255) | NULL | 运营审核人 |
| `reviewed_at` | DateTime(tz) | NULL | 审核时间 |
| `review_note` | Text | NULL | 审核备注 |
| `created_at` / `updated_at` | DateTime(tz) | NOT NULL | 时间戳 |

认证状态机（`app/models/state_machine.py` 的 `RETAILER_TRANSITIONS`）：

```text
pending  -> approved     （运营审核通过，核心路径）
pending  -> rejected     （运营拒绝，终态）
approved -> suspended    （运营暂停）
suspended -> approved    （恢复）
rejected  -> （终态）
```

审核动作（approved / rejected / suspended）会同时写入 `reviewed_by` / `reviewed_at` / `review_note`。

### 3.3 Product（`products`）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | String(36) | PK | UUID v4 |
| `sku` | String(64) | NOT NULL, UNIQUE | 三系统稳定业务关联键（`^[A-Z0-9][A-Z0-9-]{1,62}[A-Z0-9]$`） |
| `name` | String(255) | NOT NULL | 商品名 |
| `brand_id` | String(36) | FK → brands, NOT NULL | 所属品牌 |
| `wholesale_price_minor` | BigInteger | NOT NULL | 批发价最小单位整数 |
| `wholesale_price_currency` | String(3) | NOT NULL, default `USD` | ISO 4217 货币 |
| `moq` | Integer | NOT NULL, default 1 | 最小起订量（≥ 1） |
| `status` | Enum | NOT NULL, default `draft` | draft / published / archived |
| `woo_product_id` | BigInteger | NULL | Woo 商品投影 ID |
| `odoo_product_id` | BigInteger | NULL | Odoo 产品投影 ID |
| `created_at` / `updated_at` | DateTime(tz) | NOT NULL | 时间戳 |

金额与 MOQ 类型明确：批发价 = `{amount_minor: wholesale_price_minor, currency: wholesale_price_currency}`，与 `money.schema.json` 对应；`moq` 为整数，与 `product.schema.json` 的 `minimum: 1` 一致。

#### 订单行 `order_lines`（订单聚合的一部分）

| 字段 | 类型 | 约束 | 说明 |

| `order_id` | String(36) | FK → orders ON DELETE CASCADE | 所属订单 |

## 4. 外部 ID 映射

覆盖任务要求的两条完整链路：

```text
Core Product (product_id, UUID v4)
  -> woo_product_id    （WooCommerce 商品投影，整数）
  -> odoo_product_id   （Odoo 产品投影，整数）
  -> sku               （三系统共享的稳定业务关联键）

Marketplace Order (marketplace_order_id, UUID v4)
  -> woo_order_id         （WooCommerce 订单投影，整数）
  -> odoo_sale_order_id   （Odoo 销售单，整数）
  -> odoo_delivery_id     （Odoo 交货单，整数）
```

规则（`conventions.md` §2.3）：外部 ID 字段为 NULL 表示该投影尚未创建；映射由 Integration 写回 Core，Core 领域模块不直接调用 Woo / Odoo API。

## 5. 订单状态机

状态枚举与 PRD 第 6 节、`conventions.md` §8.2 一致，snake_case：

```text
draft, submitted, sent_to_odoo, odoo_confirmed, inventory_reserved,
picking_ready, shipped, completed, cancelled, sync_failed
```

### 5.1 单向推进主线

```text
draft -> submitted -> sent_to_odoo -> odoo_confirmed
      -> inventory_reserved -> picking_ready -> shipped -> completed
```

主线**只允许单向推进**；任何状态倒退（如 `shipped -> inventory_reserved`、`odoo_confirmed -> submitted`）都被拒绝并记录告警日志，抛出 `InvalidStateTransitionError`。

### 5.2 Cancelled（可明确回退的终态）

- 仅允许从发货前状态进入：`draft / submitted / sent_to_odoo / odoo_confirmed / inventory_reserved / picking_ready`。
- `shipped` 之后不可取消（退货流程留待阶段 3，见 `PRD.md` §3.2）。
- `cancelled` 是终态，不可再迁移。

### 5.3 SyncFailed（可明确回退的旁路状态）

- 允许从 Odoo 边界状态进入：`sent_to_odoo / odoo_confirmed / inventory_reserved / picking_ready`。
- 进入 `sync_failed` 时记录 `sync_failed_from`（失败前状态）；重试成功后**只允许回退到该来源状态**，不允许跳到其他状态。
- 恢复到来源状态后清空 `sync_failed_from`。

### 5.4 完整迁移表

| from \ to | 允许目标 |
| --- | --- |
| `draft` | `submitted`, `cancelled` |
| `submitted` | `sent_to_odoo`, `cancelled` |
| `sent_to_odoo` | `odoo_confirmed`, `sync_failed`, `cancelled` |
| `odoo_confirmed` | `inventory_reserved`, `sync_failed`, `cancelled` |
| `inventory_reserved` | `picking_ready`, `sync_failed`, `cancelled` |
| `picking_ready` | `shipped`, `sync_failed`, `cancelled` |
| `shipped` | `completed` |
| `completed` | （终态） |
| `cancelled` | （终态） |
| `sync_failed` | 仅 `sync_failed_from` 记录的来源状态 |

### 5.5 非法迁移的拒绝与记录

非法迁移（含状态倒退）触发：

1. 告警日志（`app.state_machine` logger，WARNING 级）；
2. 抛出 `InvalidStateTransitionError`（`app/models/state_machine.py`）。

每次**成功**迁移追加一条 `order_status_events` 审计记录（from/to/reason/actor/occurred_at），满足"跨系统编排所需的状态与审计信息"。

- 假设 Woo 与 Odoo 均使用整数自增 ID（沿用 `conventions.md` §10，`BigInteger` 兼容）。

- Retailer 的 Woo / Odoo 客户 ID 映射（`woo_customer_id` / `odoo_partner_id`）本任务**未落地**，由 ISSUE-0107（Integration 创建销售单时匹配客户）引入：NOT_TESTED。

- 订单总额、MOQ 校验、SKU 不可变等业务规则在服务层落地（ISSUE-0102 / ISSUE-0103 / ISSUE-0107），本任务只定义数据与状态机地基。
