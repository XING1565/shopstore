# PRD：B2B Faire-like Marketplace

## 1. 产品目标

构建一个参考 Faire 的 B2B 批发 marketplace，让经过认证的买家可以发现品牌、浏览商品、查看批发价、按 MOQ 下单，并由平台通过 Odoo 完成履约。

第一阶段目标是跑通最小业务闭环，不做支付。

## 2. 用户角色

### 2.1 买家 Retailer

典型用户是零售商、渠道商、采购商。

核心诉求：

- 发现适合采购的品牌
- 查看批发价
- 了解 MOQ
- 快速提交采购订单
- 跟踪订单履约状态

### 2.2 Vendor / Brand

典型用户是品牌方、供应商、供货商。

阶段一暂不提供完整品牌自助后台，由运营人员代维护品牌和商品。

后续诉求：

- 管理品牌资料
- 管理商品目录
- 查看订单
- 协作履约
- 查看销售表现

### 2.3 运营人员

负责平台日常管理。

核心诉求：

- 审核买家
- 维护品牌和商品
- 查看订单
- 处理同步失败
- 跟踪 Odoo 履约状态

### 2.4 履约人员 / 仓库人员

阶段一主要在 Odoo 中工作。

核心诉求：

- 查看销售单
- 查看交货单
- 完成拣货和发货
- 回填发货状态

### 2.5 采购人员

阶段一可以先不做完整采购自动化，后续主要在 Odoo 中工作。

核心诉求：

- 查看库存不足的商品
- 创建采购单
- 管理供应商
- 跟踪采购入库

### 2.6 财务人员

阶段一暂不做完整财务闭环，后续主要在 Odoo 中工作。

核心诉求：

- 查看发票
- 查看应收账款
- 处理对账
- 处理退货贷项

### 2.7 管理员

负责系统级管理。

核心诉求：

- 管理用户和角色
- 管理系统配置
- 管理 Woo / Odoo / Core 集成配置
- 查看日志和审计
- 管理发布、备份和恢复

## 4. 核心用户故事

### 4.1 买家注册

作为买家，我可以注册账号并提交基础公司信息，以便申请查看批发价和下单资格。

验收：

- 买家可以注册
- 注册后状态为 Pending
- 未认证买家不能查看完整批发价

### 4.2 买家认证

作为运营人员，我可以审核买家并将状态改为 Approved。

验收：

- 运营人员可以查看买家列表
- 可以修改买家认证状态
- Approved 买家可以查看批发价

### 4.3 品牌发现

作为买家，我可以浏览品牌列表并进入品牌详情页。

验收：

- 有品牌列表
- 品牌有名称、Logo、简介
- 品牌详情页展示品牌商品

### 4.4 商品浏览

作为买家，我可以浏览商品并查看商品详情。

验收：

- 商品有图片、名称、品牌、SKU
- 认证买家看到批发价
- 商品显示 MOQ

### 4.5 MOQ 校验

作为买家，我提交订单时，系统会校验数量是否满足 MOQ。

验收：

- 数量低于 MOQ 时不能提交
- 系统提示具体原因

### 4.6 无支付下单

作为认证买家，我可以提交无支付订单。

验收：

- 不进入支付流程
- 生成 Marketplace 订单
- 订单状态为 Submitted

### 4.7 Odoo 履约

作为运营人员，我希望订单进入 Odoo，并生成销售单和交货单。

验收：

- Odoo 中创建销售单
- 销售单能确认
- Odoo 生成交货单
- 仓库可以标记发货

### 4.8 订单状态查看

作为买家，我可以在前台查看订单状态。

验收：

- 订单有状态
- Odoo 发货后前台状态更新
- 同步失败时后台可见

## 7. 关键业务规则

- 未登录用户可以浏览部分公开内容
- 未认证买家不能查看完整批发价
- 未认证买家不能提交订单
- 商品必须有 SKU
- 商品必须有 MOQ
- 阶段一商品由运营 / Admin 在 Core 中创建
- Core Product 是商品业务主实体
- Woo Product 是 Core Product 的前台展示投影
- Odoo Product / SKU 是 Core Product 的 ERP 投影
- Vendor 后续提交的商品也必须先进入 Core 审核，不能直接写入 Woo 或 Odoo
- 订单数量必须满足 MOQ
- Core 是订单主权系统
- Odoo 是库存和履约主权系统
- Core 只保存 marketplace 所需数据，不复制 Odoo 全量库存、仓库、采购、财务和退货数据
- Core 必须保存 Woo Order ID、Odoo Sale Order ID、Odoo Delivery ID 等外部系统 ID 映射
- Core 不直接依赖 WooCommerce 或 Odoo API 细节，具体同步由 Integration Layer 处理
- 同一个 Core 订单不能重复创建 Odoo 销售单

## 8. 成功标准

阶段一成功标准：

```text
买家注册
  -> 运营审核
  -> 买家查看批发价
  -> 买家按 MOQ 下单
  -> Core 创建订单
  -> Odoo 创建销售单
  -> Odoo 创建交货单
  -> 仓库发货
  -> 前台显示发货状态
```
