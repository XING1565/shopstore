# 命名规范

本文件约定仓库内目录、文件、环境变量、分支与各应用内的通用命名。跨系统业务命名
（SKU、外部 ID 映射、金额/时间/状态字段）以 `packages/contracts/` 契约为准。

## 目录与文件

- 目录名、文件名一律**小写 kebab-case**（连字符分隔），如 `test-data/`、`marketplace-bridge/`。
- 命名要短且表意；不出现空白字符、大写字母或下划线（`.env.example`、`README.md` 等约定文件除外）。
- 文档文件使用中文名时不加序号前缀；同主题系列用两位数字前缀，如 `docs/issues/README.md`。
- 每个应用/包/层在自身目录下必须有 `README.md`，声明目录所有权（Owner Agent）。

## 服务 / 应用命名

| 逻辑名 | 目录名 | 说明 |
| --- | --- | --- |
| core | `apps/core` | Marketplace Core |
| woo | `apps/woo` | WordPress + WooCommerce |
| odoo | `apps/odoo` | Odoo ERP |
| integration | `apps/integration` | Integration Layer |

统一使用 `core / woo / odoo / integration` 作为模块边界词，不要在文档与代码中混用
别名（如用 `woocommerce` 代替 `woo`、用 `erp` 代替 `odoo`）。

## 环境变量

- 一律 **UPPER_SNAKE_CASE**。
- 通用变量不加前缀（`APP_ENV`、`APP_DEBUG`、`APP_PORT`、`LOG_LEVEL`）。
- 跨系统地址统一用 `<系统>_BASE_URL`：`WOO_BASE_URL`、`ODOO_BASE_URL`、`CORE_BASE_URL`。
- 系统内私有变量带系统前缀：`WP_DB_*`、`ODOO_DB_*`、`DB_*`（core 自身）。
- 模板文件命名为 `*.env.example`；真实 `.env` 不提交。
- 模板中出现的密码一律为 `change_me_in_env_file`，绝不写真实值。

## 数据库

- 库名：`shopstore_<模块>`（`shopstore_core`、`shopstore_woo`、`shopstore_odoo`）。
- 表名小写、下划线分词；前缀按平台约定（WordPress `wp_`，WooCommerce 使用 WC 内置前缀）。

## 测试数据

- 测试账号统一使用 `.test` 域名：`retailer_*@example.test`。
- 商品 SKU 使用 `DEMO-SKU-###` 固定命名空间，见 `docs/测试数据说明.md`（ISSUE-0008）。

## 代码 / 标识符

- 各应用内遵循自身生态约定：WordPress/PHP 按 WP 代码规范（函数 `snake_case`、类 `StudlyCaps`、
  插件前缀），Odoo 模块名 `snake_case`（`marketplace_connector`），Python 按 PEP 8，
  Node/TS 按生态惯例并在引入时写进各应用 README。
- 跨应用共用标识符（订单号、外部 ID）在契约未冻结前不硬编码；由 architect 的 ISSUE-0007 统一定义。
