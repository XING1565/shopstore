## 1. 范围与定位

本任务冻结 Product 从 Core 创建、投影到 Woo 与 Odoo 的完整链路契约，明确三系统边界。一句话总结：

```text
Core 拥有商品的批发价与 MOQ 真相；Woo 只做前台展示投影；Odoo 只拥有 SKU 与库存。
```

契约落点（单一事实来源）：

| 落点 | 内容 |
| --- | --- |
| `packages/contracts/schemas/product.schema.json` | Core Product 业务主实体（批发价 / MOQ 真相 + 外部 ID 映射） |
| `packages/contracts/schemas/product-projections.schema.json` | Woo / Odoo 投影边界（明确两者不持有批发价 / MOQ） |
| `packages/contracts/events/product-events.schema.json` | 商品领域事件负载（created / published / updated / archived） |
| `packages/contracts/openapi/openapi.yaml` | Core HTTP 接口（Product 创建 / 查询 / 更新 / 发布 / 下架） |
| `packages/contracts/conventions.md` | ID 映射、SKU、金额、时间、状态、版本策略等通用约定 |

## 2. 商品创建链路

阶段一不做 Vendor Portal，商品由运营 / Admin 在 Core 创建。

### 2.1 主链路（创建 → 发布 → 投影 → 写回）

```text
运营 / Admin
  └─> POST /api/v1/products               创建 Core Product（status=draft）
        Core 校验品牌、SKU 唯一、批发价、MOQ（≥1）
  └─> POST /api/v1/products/{id}/publish  发布（draft → published）
        Core 发出 catalog.product.published 事件（含完整商品快照）
  └─> Integration 消费事件
        ├─> Woo Adapter 创建/更新 Woo Product（展示投影）
        └─> Odoo Adapter 创建/更新 Odoo Product/SKU（履约投影）
  └─> Integration 写回外部 ID
        Core 保存 woo_product_id / odoo_product_id 到 external_ids
```

### 2.2 状态与投影对应关系

| 商品状态 | 投影状态 |
| --- | --- |
| `draft` | 尚未投影到 Woo / Odoo（`external_ids` 为空） |
| `published` | 已投影（发布事件触发 Integration 创建投影并写回 ID） |
| `archived` | Woo 隐藏、Odoo 停用（下架事件触发） |

发布为**异步投影**：`publish` 响应返回时 `external_ids` 可能仍为空，投影由 Integration 完成后写回。这与 `conventions.md` §2.3「外部 ID 字段缺失表示投影尚未创建」一致。

### 2.3 更新链路

```text
运营 / Admin
  └─> PATCH /api/v1/products/{id}         更新名称 / 品牌 / 批发价 / MOQ
        SKU 一经发布不可修改（改 SKU = 新产品，需迁移并重新映射，见 conventions.md §3）
        Core 发出 catalog.product.updated 事件
  └─> Integration 同步 Woo / Odoo 投影
```

## 3. 三系统投影契约

### 3.1 字段主权表

| 字段 | Core | Woo | Odoo | 说明 |
| --- | --- | --- | --- | --- |
| `sku` | 真相 | 投影（Woo `sku`） | 投影（Odoo `default_code`） | 三系统一致的稳定业务关联键，不可变 |
| `name` | 真相 | 投影 | 投影 | |
| `brand` | 真相（`brand_id`） | 展示用品牌名 | 不持有 | |
| `wholesale_price` 批发价 | **真相** | 不持有（渲染时从 Core 读） | 不持有 | Woo 后台不得手改并覆盖 Core |
| `moq` MOQ | **真相** | 不持有（渲染时从 Core 读） | 不持有 | 下单校验回 Core |
| 库存 `qty_available` | 不持有 | 不持有 | **主权** | Odoo 维护，阶段一不回传、不复制到 Core |
| 外部 ID 映射 | **主权**（`woo_product_id`/`odoo_product_id`） | — | — | Integration 写回 Core |

### 3.2 三种投影

```text
Core Product（product.schema.json）
  ├─> Woo Product   （WooProductProjection：展示投影，无批发价 / MOQ）
  └─> Odoo Product  （OdooProductProjection：SKU + 名称，无批发价 / MOQ，库存归 Odoo）
```

投影 schema 用 `additionalProperties: false` 强制排除批发价与 MOQ，从契约层面杜绝「投影方误存真相」。

### 3.3 边界红线

1. Woo 前台展示批发价 / MOQ：由 `marketplace-bridge` 插件以买家身份调 Core API 渲染，**不落地 Woo**。
2. Woo 下单钩子回 Core 做认证与 MOQ 校验；禁止 Woo 后台手改批发价 / MOQ 覆盖 Core。
3. Odoo 库存数量由 Odoo 维护，Core 不复制库存流水。
4. Core 领域模块不直接调用 Woo / Odoo API；投影由 Integration 完成。

## 4. 外部 ID 映射规则

```text
Core Product (product_id, UUID v4)
  ├─> woo_product_id    （WooCommerce 商品投影，整数）
  ├─> odoo_product_id   （Odoo 产品投影，整数）
  └─> sku               （三系统共享的稳定业务关联键）
```

- 外部 ID 字段**缺失**（不在 JSON 中）表示投影尚未创建，不用 `null`（`conventions.md` §2.3；DB 层对应 NULL）。
- 映射由 Integration 写回 Core；Core 领域模块不直接调用 Woo / Odoo API。
- Woo / Odoo 均为整数自增 ID（`BigInteger` 兼容），Core 自生成 ID 为 UUID v4。
- 完整结构以 `schemas/external-ids.schema.json` 的 `ProductExternalIds` 为准。

## 5. 契约文件与使用方式

| 角色 | 使用方式 |
| --- | --- |
| dev（ISSUE-0103 Core API） | 按 `openapi.yaml` 的 Product 端点与 `schemas/product.schema.json` 实现接口与校验 |
| dev（ISSUE-0104 Woo 桥接） | 按 `WooProductProjection` 做展示投影；批发价 / MOQ 走 Core API 渲染 |
| dev（ISSUE-0107 Integration） | 消费 `catalog.product.published/updated/archived` 事件，按投影 schema 写入 Woo / Odoo，写回外部 ID |
| qa | 按 schema 做契约校验；用 `product.schema.json` 断言批发价 / MOQ 字段类型，用投影 schema 断言 Woo / Odoo 不落批发价 / MOQ |

### 5.1 金额 / 时间 / 状态命名与版本策略

沿用 `conventions.md`，本任务仅确认商品相关项：

- 金额：批发价 = `{ amount_minor, currency }`（`money.schema.json`），最小单位整数，禁止浮点数；对应数据模型 `wholesale_price_minor` / `wholesale_price_currency`。
- 时间：RFC 3339 UTC，`Z` 结尾，`*_at` 后缀（`timestamp.schema.json`）。
- 状态：商品 `draft / published / archived`（`conventions.md` §8.3）；买家 / 订单状态见 §8.1 / §8.2。
- API 版本：URL 路径主版本 `/api/v1/...`，破坏性变更升主版本并保留旧版本冻结期；非破坏性新增不升版本（`conventions.md` §9）。

## 7. 假设与未验证项（NOT_TESTED）

- Woo 与 Odoo 均为整数自增 ID（沿用 `conventions.md` §10，`BigInteger` 兼容）。
- 阶段一基础货币 USD（`exponent = 2`）。
- 多币种换算与舍入策略：NOT_TESTED（留待阶段一后续 issue）。
- Woo 桥接插件如何以买家身份调用 Core API（认证 / 鉴权细节）：由 ISSUE-0103 / ISSUE-0104 落地，本契约只规定「未认证买家不可见批发价」这一语义。
- 库存回传（Odoo → Core 的 `qty_available`）：阶段一不做，NOT_TESTED。
