## 5. 初始化 / 导入（幂等）

任何一次初始化都可安全重复执行，重复执行不产生不可控重复数据（按 SKU / username / ref 唯一键 upsert）。

```bash
# Woo：每次容器启动自动执行 docker/provision.sh（含 ISSUE-0003 + ISSUE-0008 seed）
docker compose -f apps/woo/compose.yaml up -d --build

# Odoo：首次 all（init→provision→verify），日常 provision/verify
bash apps/odoo/config/provision/run.sh all        # 或 run.ps1 -Action all
```

也可在服务已运行时单独重放测试数据：

```bash
bash packages/test-data/scripts/init-test-data.sh          # Woo + Odoo 幂等导入
powershell -ExecutionPolicy Bypass -File packages/test-data/scripts/init-test-data.ps1
```

## 6. 重置测试数据

重置 = 删除本地数据卷并重新初始化（回到“无数据 → 全量导入”的干净基线）。**仅限本地/一次性环境，不可用于共享环境。**

```bash
CONFIRM=yes bash packages/test-data/scripts/reset-test-data.sh
powershell ... # Windows：设置 $env:CONFIRM='yes' 后运行 packages/test-data/scripts/reset-test-data.ps1
```

> 项目级一键编排（start/stop/logs/backup…）由 ops（ISSUE-0010）在 `infra/scripts` 固化，
> 本脚本只负责测试数据层初始化 / 重置。

## 7. QA 验收路径

1. 全新环境按 `docs/本地开发说明.md` 启动 Woo / Odoo / Core。
2. 执行第 5 节初始化。
3. 校验：
   - Woo：`/my-account` 可用 retailer_approved / retailer_pending 登录；后台可见 `Demo Brand A` 与 DEMO-SKU-001/002。
   - Odoo：`run.sh verify` 全 PASS（含 DEMO-RTL-001/002、SKU 与库存）。
   - SKU 存在性断言见 ISSUE-0009（tests/smoke）。
